# Contributing to AURA

Thank you for your interest in contributing to **AURA – Your Personal AI Companion**!

AURA is an advanced Generative AI-powered personal assistant designed to help users learn, communicate, work, and grow through personalized AI interactions.

We welcome contributions, suggestions, bug reports, feature requests, and improvements.

## 1. Project Overview

AURA is built around three core modes:

- **Default Mode:** An intelligent personal AI assistant.
- **Preparation Mode:** An adaptive AI tutor for learning and skill development.
- **Communication Mode:** A personal communication coach for improving speaking and professional communication.

The project also aims to integrate voice AI, virtual avatars, long-term memory, multimodal intelligence, and specialized AI agents.

## 2. How to Contribute

You can contribute by:

- Improving frontend UI/UX.
- Developing backend APIs and services.
- Integrating LLMs and Generative AI capabilities.
- Improving ML-based personalization and evaluation.
- Working on voice recognition and speech generation.
- Developing avatar interactions and animations.
- Writing documentation and test cases.
- Reporting bugs and suggesting new features.

## 3. Development Guidelines

Please follow these guidelines:

- Write clean, readable, and maintainable code.
- Follow consistent naming conventions.
- Keep functions and modules focused on specific responsibilities.
- Add comments where the implementation needs clarification.
- Avoid unnecessary dependencies.
- Test your changes before submitting them.
- Update documentation when functionality changes.

## 4. Git Workflow

Follow this workflow when contributing:

1. Fork the repository.
2. Clone your fork locally.
3. Create a separate feature branch.
4. Implement your changes.
5. Test your implementation.
6. Commit your changes with a meaningful message.
7. Push your branch.
8. Open a Pull Request describing your contribution.

Example:

```bash
git clone <repository-url>
git checkout -b feature/feature-name
git add .
git commit -m "Add: meaningful feature description"
git push origin feature/feature-name
```

## 5. Branch Naming Convention

Use descriptive branch names:

- `feature/feature-name`
- `fix/bug-description`
- `docs/documentation-update`
- `refactor/module-name`
- `test/test-description`

## 6. Commit Message Convention

Use clear commit messages:

- `Add: new functionality`
- `Fix: resolve an issue`
- `Update: improve existing functionality`
- `Refactor: improve code structure`
- `Docs: update documentation`
- `Test: add or update tests`

## 7. Pull Request Guidelines

Every Pull Request should include:

- A clear title.
- Description of the changes.
- Reason for the contribution.
- Relevant screenshots or demonstrations, if applicable.
- Testing details.
- Related issue number, if applicable.

Keep Pull Requests focused and avoid combining unrelated changes.

## 8. Code Quality and Security

- Never commit API keys, passwords, access tokens, or private credentials.
- Use environment variables for sensitive configuration.
- Keep `.env` files out of version control.
- Validate user inputs.
- Follow secure coding practices.
- Never execute untrusted AI-generated code without proper sandboxing.

## 9. Reporting Issues

When reporting a bug, include:

- A clear description of the problem.
- Steps to reproduce it.
- Expected behavior.
- Actual behavior.
- Error messages or screenshots, if available.
- Relevant environment details.

For feature requests, explain the problem the feature solves and its expected benefits.

## 10. Community Expectations

We believe in:

- Respectful and constructive communication.
- Collaboration and knowledge sharing.
- Meaningful technical discussions.
- Continuous learning and improvement.
- Building reliable, user-focused AI systems.

## 11. Project Status

AURA is under active development. Features, architecture, and implementation details may evolve as the project progresses.

Contributions should align with the project's long-term vision and development roadmap.
